# Getting started

1. From the project that uses the skill, run `npx skills add miguelalcalde/lead-research-skills --skill lead-research` after publication, or expose this skill's `SKILL.md` to a compatible harness locally. The installer copies `skills/lead-research/` with its bundled references and scripts. The harness supplies access to its own records and write tools; no data source or target database is encoded here. A user may request one operation or any subset across an approved list.
2. Check whether the host harness already provides authenticated AI Gateway model and Exa Search tools; if so, reuse them and do not request a second key. Otherwise, choose a Vercel team with Gateway access, create an [AI Gateway API key](https://vercel.com/docs/ai-gateway/authentication-and-byok/api-keys), and configure it in the harness's secret store or environment (`AI_GATEWAY_API_KEY` when supported). Copy the key on creation; do not put it in prompts, example files, version control or command arguments. Gateway's Exa tool uses the same credential, not a separate Exa key. Team permissions, spend attribution, and credits are described in [Gateway setup](https://vercel.com/docs/ai-gateway/getting-started).
3. Check that `openai/gpt-6-luna` is available to your team. Default to it for interpretation. Select another available model explicitly if required; do not silently fall back. The host harness decides how it routes model and search calls through AI Gateway.
4. If the harness already provides AI Gateway Exa Search and model tools, use those with the operation-specific settings in [shared search](common/search.md). If it does not, point its operator to the [AI SDK introduction](https://ai-sdk.dev/docs/introduction), [Gateway getting started](https://vercel.com/docs/ai-gateway/getting-started) and [Gateway Exa Search configuration](https://vercel.com/docs/ai-gateway/models-and-providers/web-search) to add those capabilities **to the harness**. Check tool access and team key provisioning before running anything. The skill itself ships no npm package, paid-search executable or automatic setup and should report a missing-tool blocker rather than silently switch search providers.
5. Agree on allowed public inputs, selected operations, maximum record count, search-call budget and review/write policy. The host should snapshot record identity before research and not accidentally overwrite existing data. Start with a small approved pilot; synthetic fixtures are only for offline tests. Search/model calls can incur charges, and a search-call limit is not by itself a hard dollar cap. Keep inputs and any cached results private and check freshness before reuse.
